# Design

## Context
Ссылки на требования и контракт 1.0.0 — в proposal.md; общий design — sdd-specs/openspec/changes/archive/2026-10-27-add-grid-model-workflow/design.md.

## Decisions
Features/GridModels: типизированные DTO, GridRules для проверки и переходов, GridStore для PostgreSQL, MapGridModels для Minimal API. Npgsql 10.0.0. В пилоте один JSONB-документ состояния с транзакционной блокировкой SELECT FOR UPDATE; это сохраняет атомарность revision, версий и журнала между репликами. Альтернатива — нормализованные таблицы — нужна при росте данных, пока добавляет миграционную сложность. Проверка тела до сохранения, параметризованные запросы. Ошибка откатывает транзакцию. История неизменяема через API.
Начальная запись создаётся INSERT ON CONFLICT DO NOTHING, содержит три демонстрационные модели. Тесты WebApplicationFactory используют отдельную схему PostgreSQL на тестовый класс, реальные транзакции и повторное открытие хранилища.

## Развёртывание (Kubernetes)
ConnectionStrings__GridModels задаётся Secret, PostgreSQL 17 с PVC 1Gi; манифест в deploy/k8s/postgres.yaml. Проверка готовности обращается к БД. API продолжает работать без локального диска. SDK локально отсутствует: сборка и xUnit выполняются в контейнере .NET 10.

## Risks / Trade-offs
Глобальная блокировка подходит малому демонстрационному реестру; нагрузочное использование требует нормализации. Таймаут подключения 5 с. Создание схемы идемпотентно, пароль только для локального демо.

## Migration Plan
Применить PostgreSQL и Secret, дождаться готовности, затем обновить API. Откат образа не удаляет PVC. Удаление хранилища не автоматизируется.
