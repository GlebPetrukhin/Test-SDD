# Замечания бэкенда к тест-кейсам

## BACK-01: код отказа submit в [grid-models-28.1]

Статус: решение принято пользователем — «Пусть будет `409 invalid_transition`». Ожидание кейса подтверждено, блокировка планирования снята. Исправление реализации и проверка тестом ещё не выполнены.

В [test-cases.md](../../../../sdd-specs/openspec/changes/compare-model-versions/test-cases.md) кейс ожидает `409 invalid_transition` при submit ошибочной версии в статусе draft, с актуальной revision и существующей организацией.

В текущем `src/Sdd.Api/Features/GridModels/GridRules.cs` переход `draft + submit` разрешён таблицей переходов. Последующая проверка `version.Issues.Count > 0` вызывает `Invalid(...)`, то есть `400 validation`, до изменения статуса. `409 invalid_transition` используется, когда сам переход отсутствует в таблице.

Принятое решение: submit версии в статусе draft с непустым issues, актуальной revision и существующей организацией возвращает `409 invalid_transition` с сохранением документов, issues, статусов и состояния модели. Прежнее предложение бэкенда использовать `400 validation` не принято. Ожидание в test-cases.md уже соответствует решению и правки не требует.

В реализации сначала добавить автотест по [grid-models-28.1], подтвердить его падение на текущем `400 validation`, затем исправить отказ submit. Изменение ограничено этим условием: коды остальных ошибок и поведение approve/publish не переопределяются. Схема ответа Error и набор допустимых HTTP-ответов уже описаны контрактом 1.0.0; файл OpenAPI не меняется.
