# sdd-specs — требования продукта (OpenSpec store)

Хранилище спецификаций: общее для всех приложений — **поведение** (дельты `spec.md`), **стык** бэка и фронта
(`design.md` изменения и контракты `contracts/*.yaml`) и **тест-кейсы** (`test-cases.md`). Кода и автотестов здесь нет.
Реализация — в `../sdd-backend` и `../sdd-frontend`: у них свой `openspec/` (схема `sdd-app`) с локальными изменениями
`<изменение>-back` / `-front`, а это хранилище они подключают только для чтения.

## Правила для агента
1. Все правила оформления артефактов — в `openspec/config.yaml`; они приходят в инструкциях OpenSpec автоматически.
2. При `/opsx:explore` и `/opsx:new` можно читать код в `../sdd-backend` и `../sdd-frontend`, чтобы понять текущее состояние, но не менять его.
3. Каждый сценарий получает стабильный ID `[<capability>-<NN>]`; ID не меняются и не переиспользуются.
4. `design.md` изменения — только стык (кто что проверяет, ошибки и коды, асинхронность, форматы, версия контракта).
   Внутренности приложений сюда не пишутся — это `design.md` их локальных изменений.
5. Контракт — `contracts/<capability>-api.yaml` (OpenAPI 3.1); изменился — поднять `info.version` и записать версию в `design.md`.
6. `test-cases.md`: кейсы по каждому сценарию изменения (ID `<сценарий>.<n>`), поле Automation начинается с репозитория-владельца
   (`sdd-backend/...` или `sdd-frontend/...`). Артефакт добавляет схема `sdd` из `../openspec-sdd`; схему правят там.
7. `tasks.md` — карта по репозиториям: локальные изменения приложений и ID их кейсов, приёмка, архивация. Не чек-лист разработчика.
8. Перед тем как сказать, что изменение готово к ревью, — `openspec validate <изменение> --strict`.
9. Архивация: сначала локальные изменения приложений заархивированы, затем `openspec-sdd trace-check --strict`, затем
   `openspec archive <изменение>` и сразу `openspec-sdd merge-test-cases <изменение>` (каталог руками не сливать), затем Gaps.

## Структура
- `openspec/specs/` — действующие спецификации (`spec.md`) и каталоги тест-кейсов (`test-cases.md`), `openspec/changes/` — изменения в работе, `changes/archive/` — завершённые
- `contracts/` — контракты API (OpenAPI 3.1), по файлу на capability
- `openspec-sdd.json` — настройки дополнения openspec-sdd для этого хранилища (где искать автотесты для trace-check)
- `workspace/` — общие для команды скрипты: `setup.*` (рабочее место), `deploy.*` (развёртывание в k8s), `open.*` (открыть приложение); `workspace/root/` — README и запускалки для корня SDD
