# Design

## Context

Бэкенд — ASP.NET Core Minimal API, фронт — Angular, оба в Kubernetes; фронт обращается к бэку по относительному пути `/api/...` через nginx (в кластере) или proxy.conf.json (локально). Мотивация — в proposal.md.

## Goals / Non-Goals

**Goals:**
- Зафиксировать контракт `GET /api/status`, по которому фронт и бэк работают независимо.
- Версию сборки задавать конфигурацией развёртывания, а не кодом.

**Non-Goals:**
- Не объединять с техническими пробами `/healthz/*`: пробы — для кластера, статус — для пользователя; их формат и доступность могут меняться независимо.

## Контракт API

`GET /api/status` — без авторизации.

Ответ `200 OK`, `Content-Type: application/json`:

```json
{ "status": "ok", "version": "1.4.2" }
```

| Поле | Тип | Описание |
|---|---|---|
| `status` | string | Всегда `ok`, если сервис смог ответить |
| `version` | string | Значение переменной окружения `APP_VERSION`; `dev`, если не задана |

Любой другой исход (сетевая ошибка, 5xx, таймаут) фронт трактует как «Система недоступна».

## Decisions

- **Версия из `APP_VERSION`**, а не из сборки (AssemblyVersion): один и тот же образ можно пометить при развёртывании, конфигурация через env одинакова на Windows и Linux. Альтернатива — вшивать версию на этапе `docker build` — отложена до появления CI.
- **Фронт запрашивает статус один раз при открытии страницы**, состояние — в сигнале сервиса. Альтернатива с периодическим опросом вынесена за рамки (proposal: Out of scope).
- **E2E-тесты фронта мокают `/api/status`** (сценарии 03, 04), поэтому не зависят от запущенного бэка; сквозная проверка на стенде — smoke-тест с тегом `@smoke` по сценарию 03.

## Развёртывание (Kubernetes)

- sdd-backend: в `deploy/k8s/deployment.yaml` добавить переменную `APP_VERSION` (по умолчанию `dev`). Портов, томов и новых сервисов не требуется.

## Risks / Trade-offs

- [Публичный эндпоинт раскрывает версию] → для учебного контура приемлемо; для боевых систем решить через отдельный change.
