# Proposal

## Why

Пользователь и команда сейчас не видят, жив ли бэкенд и какая версия развёрнута: при сбое фронт молча показывает пустую страницу. Заодно это первая сквозная фича, на которой проверяем весь контур SDD: спецификация → контракт API → бэк → фронт → автотесты → Kubernetes.

## What Changes

- **sdd-backend**: новый публичный эндпоинт статуса сервиса с версией развёрнутой сборки.
- **sdd-frontend**: на главной странице блок «Статус системы»: доступен / недоступен и версия бэкенда.
- **Развёртывание**: версия сборки передаётся бэкенду через переменную окружения в манифесте Kubernetes.

Out of scope:
- Проверка зависимостей (БД, внешние сервисы) — их пока нет.
- Автообновление статуса без перезагрузки страницы.
- Технические пробы Kubernetes (`/healthz/*`) — они уже есть и в спецификацию не входят.

## Capabilities

### New Capabilities
- `system-status`: отображение доступности системы и версии развёрнутого бэкенда для пользователя.

### Modified Capabilities
<!-- нет -->

## Impact

- API: новый `GET /api/status` (контракт — в design.md).
- sdd-backend: Program.cs, интеграционные тесты, `deploy/k8s/deployment.yaml` (переменная `APP_VERSION`).
- sdd-frontend: главная страница, сервис статуса, unit- и E2E-тесты.
