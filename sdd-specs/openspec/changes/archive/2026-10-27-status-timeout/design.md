# Design — стык

## Context

Сценарий `[system-status-04]` получает срок: «Система недоступна» не позже чем через 5 с, если бэкенд молчит.
Затрагивает только фронт; бэкенд и контракт не меняются.

## Decisions

- **Кто отвечает за срок.** Фронт: ждёт ответ `GET /api/status` не дольше 5 с, затем отменяет запрос и показывает
  «Система недоступна». Бэкенд срок не обеспечивает и ничего не меняет — медленный ответ для фронта то же, что отсутствие ответа.
- **Что считается «не ответил».** Нет ответа (включая заголовки) за 5 с с момента отправки запроса. Ответ, пришедший позже, игнорируется.
- **Ошибка vs. таймаут.** Для пользователя одно и то же сообщение; различать их в интерфейсе не нужно.
- **Контракт.** `contracts/system-status-api.yaml` без изменений, версия 1.0.0.

## Risks / Trade-offs

- На медленной сети реальный бэкенд, отвечающий дольше 5 с, будет показан как недоступный — это осознанно: для статуса
  важнее быстрая обратная связь.
