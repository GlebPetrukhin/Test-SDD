# Design

## Context

Обрезка уже реализована в `SystemStatusEndpoints.Create` (`Trim()`, пустое → `dev`). Мотивация — в proposal.md.

## Goals / Non-Goals

**Goals:** закрепить поведение сценарием `[system-status-05]` и тестами на уровне unit и API.

**Non-Goals:** менять код или контракт `GET /api/status` — контракт из `2026-10-27-add-system-status/design.md` остаётся прежним.

## Decisions

- Проверка на двух уровнях: unit — граничные значения нормализации, integration — что переменная окружения с пробелами доходит до ответа API нормализованной. Альтернатива «только unit» не ловит потерю нормализации при смене способа чтения конфигурации.
- Кейс `[system-status-02.3]` больше не проверяет обрезку попутно: это теперь отдельные кейсы сценария 05.

## Risks / Trade-offs

- [Тесты сразу зелёные — поведение уже есть] → это ожидаемо: изменение фиксирует существующее поведение, а не добавляет новое.
