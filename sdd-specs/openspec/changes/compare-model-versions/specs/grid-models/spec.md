# Spec Delta

## ADDED Requirements

### Requirement: Выбор двух версий одной модели для сравнения

Для отдельного сравнения система SHALL позволять пользователю выбрать любые две различные сохранённые версии одной модели в качестве «Было» и «Стало» независимо от их статусов и наличия опубликованной версии. Результат SHALL явно указывать выбранные версии и направление сравнения.

#### Scenario: [grid-models-09] Выбор произвольных версий
- **WHEN** пользователь выбирает две различные сохранённые версии одной модели как «Было» и «Стало» и запускает сравнение
- **THEN** система показывает результат именно для выбранной пары с обозначением обеих версий
- **AND** доступны версии в состояниях draft, review, approved, published и rejected
- **AND** версии не обязаны быть соседними или иметь общую базовую опубликованную версию

#### Scenario: [grid-models-10] Сравнение без опубликованной версии
- **WHEN** у модели нет опубликованной версии и пользователь сравнивает два её сохранённых черновика
- **THEN** система показывает сравнение выбранных черновиков

### Requirement: Изменения объектов между выбранными версиями

Система SHALL сопоставлять однозначно определяемые объекты выбранных версий по ID и показывать добавленные, удалённые и изменённые объекты относительно направления «Было → Стало». Система SHALL сравнивать название, тип, напряжение и связи; для изменённых полей показывать значения обеих версий. Сравнение SHALL сохранять данные и статусы версий.

#### Scenario: [grid-models-11] Значения изменённых полей
- **WHEN** в версии «Было» объект с ID «line-1» имеет название «Линия 1» и напряжение 110 кВ, а в версии «Стало» тот же объект имеет название «Линия Север» и напряжение 220 кВ
- **THEN** объект показан как изменённый
- **AND** для названия показано «Линия 1 → Линия Север», а для напряжения — «110 → 220» кВ
- **AND** данные и статусы сравниваемых версий сохраняются

#### Scenario: [grid-models-12] Добавленные и удалённые объекты
- **WHEN** объект «line-2» есть только в версии «Стало», а объект «line-3» — только в версии «Было»
- **THEN** объект «line-2» показан как добавленный, а объект «line-3» — как удалённый

#### Scenario: [grid-models-13] Обратное направление сравнения
- **WHEN** пользователь меняет местами версии «Было» и «Стало» и повторяет сравнение
- **THEN** значения полей показаны в обратном направлении
- **AND** ранее добавленные объекты показаны как удалённые, а ранее удалённые — как добавленные

#### Scenario: [grid-models-18] Изменение типа объекта
- **WHEN** у объекта с одинаковым уникальным ID в обеих версиях тип изменён с «busbar» на «substation», а остальные поля совпадают
- **THEN** объект показан как изменённый, а для типа показано «busbar → substation»

#### Scenario: [grid-models-19] Изменение состава связей
- **WHEN** у объекта с одинаковым уникальным ID в обеих версиях связи изменены с «[bus-1]» на «[bus-1, bus-2]», а остальные поля совпадают
- **THEN** объект показан как изменённый, а для связей показано «[bus-1] → [bus-1, bus-2]»

### Requirement: Данные вне сравнения и смена ID

Система SHALL игнорировать порядок объектов в документе и метаданные версий при определении различий данных модели. Если объект получает другой ID, система SHALL показывать удаление объекта со старым ID и добавление объекта с новым ID, даже когда остальные поля совпадают.

#### Scenario: [grid-models-20] Перестановка объектов и разные метаданные
- **WHEN** две версии содержат одинаковые объекты с уникальными ID в разном порядке, а различаются только описанием изменения, организацией, временем создания, статусом или базовой версией
- **THEN** система показывает «Различий нет»
- **AND** версии и направление сравнения по-прежнему явно указаны

#### Scenario: [grid-models-21] Изменение ID при одинаковых остальных полях
- **WHEN** объект «line-1» присутствует только в версии «Было», объект «line-2» — только в версии «Стало», а их название, тип, напряжение и связи совпадают
- **THEN** «line-1» показан как удалённый, а «line-2» — как добавленный
- **AND** система не показывает эту пару как изменение поля ID одного объекта

### Requirement: Значимость порядка связей объекта

Система SHALL считать перестановку тех же связей однозначно сопоставленного объекта изменением поля связей и показывать его значения «было → стало» с сохранением порядка каждой версии.

#### Scenario: [grid-models-17] Перестановка связей без изменения их состава
- **WHEN** у однозначно сопоставленного объекта «line-1» в версии «Было» связи указаны в порядке «bus-1, bus-2», а в версии «Стало» — «bus-2, bus-1», при этом остальные поля совпадают
- **THEN** объект «line-1» показан как изменённый
- **AND** для поля связей показано «[bus-1, bus-2] → [bus-2, bus-1]»
- **AND** результат не обозначается как «Различий нет»

### Requirement: Отсутствие различий между версиями

Система SHALL явно показывать отсутствие различий в данных объектов двух выбранных версий только при полном результате сравнения.

#### Scenario: [grid-models-14] Одинаковые данные разных версий
- **WHEN** пользователь сравнивает две различные версии с одинаковыми данными объектов и все объекты могут быть однозначно сопоставлены
- **THEN** система показывает «Различий нет»
- **AND** списки добавленных, удалённых и изменённых объектов пусты

### Requirement: Неполное сравнение при повторяющихся ID

При повторении ID в любой из выбранных версий система SHALL показывать однозначно определяемые различия по остальным ID и исключать объекты с повторяющимся ID в обеих версиях из списков различий. Система SHALL указывать исключённые ID и показывать предупреждение «Результат сравнения неполный: есть объекты с повторяющимися ID». Неполный результат SHALL NOT обозначаться как «Различий нет».

#### Scenario: [grid-models-15] Однозначные различия при повторяющемся ID
- **WHEN** в версии «Было» ID «line-1» встречается дважды, а в версии «Стало» — один раз, и объект с уникальным в обеих версиях ID «line-2» изменил напряжение со 110 на 220 кВ
- **THEN** для объекта «line-2» показано изменение напряжения «110 → 220» кВ
- **AND** объекты с ID «line-1» из обеих версий не показаны как добавленные, удалённые или изменённые
- **AND** система показывает предупреждение «Результат сравнения неполный: есть объекты с повторяющимися ID» и указывает исключённый ID «line-1»

#### Scenario: [grid-models-16] В проверенной части различий нет
- **WHEN** повторяющиеся или пустые ID препятствуют полному сравнению, есть однозначно сравнимые объекты и среди них различий нет
- **THEN** система сохраняет предупреждения о причинах неполноты и сведения об исключённых объектах
- **AND** система показывает «В однозначно сравнимой части различий нет» вместо «Различий нет»

### Requirement: Исключение объектов с пустыми ID

Система SHALL исключать из сравнения объекты с пустым или состоящим только из пробелов ID и показывать предупреждение «Результат сравнения неполный: есть объекты с пустым ID». Для каждой затронутой версии система SHALL указывать количество таких объектов. Остальные однозначно определяемые различия SHALL отображаться; предупреждения о повторяющихся ID SHALL сохраняться, если они также есть.

#### Scenario: [grid-models-22] Пустой ID и ID из пробелов
- **WHEN** версия «Было» содержит один объект с пустым ID, версия «Стало» — один объект с ID из трёх пробелов, а объект с уникальным ID «line-2» изменил напряжение со 110 на 220 кВ
- **THEN** для «line-2» показано «110 → 220» кВ, а объекты с пустым и состоящим из пробелов ID исключены из списков различий
- **AND** показано предупреждение «Результат сравнения неполный: есть объекты с пустым ID»
- **AND** для каждой выбранной версии указано, что исключён один объект с пустым ID
- **AND** при наличии повторяющихся непустых ID также показаны предупреждение о них и исключённые ID

### Requirement: Отсутствие однозначно сравнимых объектов

Если из-за повторяющихся или пустых ID не осталось ни одного однозначно сравнимого объекта, система SHALL показывать «Нет объектов для однозначного сравнения», сохранять предупреждения и сведения об исключениях. Система SHALL NOT представлять такой результат как полное сравнение либо отсутствие различий.

#### Scenario: [grid-models-23] Все объекты исключены
- **WHEN** все объекты выбранной пары исключены из сравнения из-за повторяющихся или пустых ID
- **THEN** показано «Нет объектов для однозначного сравнения» вместе с предупреждениями о неполноте и сведениями об исключениях
- **AND** сообщение «Различий нет» не показывается

### Requirement: Недопустимый или незавершённый выбор версий

Система SHALL предлагать для выбора версии одной модели. При наличии менее двух версий, незавершённом выборе, выборе одной версии дважды или версий разных моделей система SHALL не запускать сравнение и объяснять причину. Прежний результат SHALL NOT отображаться как результат недопустимой или незавершённой пары.

#### Scenario: [grid-models-24] Меньше двух версий
- **WHEN** у выбранной модели нет сохранённых версий или есть только одна
- **THEN** сравнение не запускается, показано «Для сравнения нужны две версии одной модели»

#### Scenario: [grid-models-25] Вторая версия не выбрана
- **WHEN** у модели есть минимум две версии, но пользователь не завершил выбор «Было» и «Стало»
- **THEN** сравнение не запускается, показано «Выберите версии «Было» и «Стало»»

#### Scenario: [grid-models-26] Одна версия выбрана дважды
- **WHEN** для «Было» и «Стало» выбрана одна и та же сохранённая версия
- **THEN** сравнение не запускается, показано «Выберите две разные версии»

#### Scenario: [grid-models-27] Версии разных моделей
- **WHEN** выбранная пара содержит версии разных моделей
- **THEN** сравнение не запускается, показано «Можно сравнивать только версии одной модели»

### Requirement: Сравнение сохранённых значений с ошибками проверки

Система SHALL допускать сравнение сохранённых версий с неизвестным типом объекта, недопустимым напряжением или несуществующими ссылками. Если ID позволяет однозначное сопоставление, система SHALL сравнивать сохранённые значения без исправления этих ошибок. Такие ошибки сами по себе SHALL NOT делать результат неполным или исключать объект. Действующие ограничения согласования версий SHALL сохраняться.

#### Scenario: [grid-models-28] Различия в значениях с ошибками проверки
- **WHEN** у однозначно определяемого объекта в версии «Было» тип «unknown-a», напряжение −1 кВ и ссылка «missing-a», а в версии «Стало» — тип «unknown-b», напряжение 0 кВ и ссылка «missing-b», при этом оба типа неизвестны и обе ссылки не существуют
- **THEN** показаны изменения сохранённых типа, напряжения и связей со значениями обеих версий
- **AND** при отсутствии проблем с ID результат не помечен как неполный
- **AND** ошибки проверки и запрет отправки ошибочной версии на согласование сохраняются

### Requirement: Ошибка получения данных и принадлежность результата паре

Если данные выбранной пары не удалось получить, система SHALL показывать «Не удалось выполнить сравнение» и действие «Повторить» для текущей выбранной допустимой пары. При смене пары или направления система SHALL убирать прежний результат. Результат и ошибка SHALL относиться к текущей явно указанной паре; результат ранее выбранной пары SHALL NOT подменять их.

#### Scenario: [grid-models-29] Ошибка и повтор сравнения
- **WHEN** пользователь выбрал допустимую пару, но данные для сравнения не удалось получить
- **THEN** показаны «Не удалось выполнить сравнение» и действие «Повторить»
- **AND** ошибка не представлена как отсутствие различий или неполное сравнение
- **AND** повтор выполняется для текущей выбранной допустимой пары и при успехе показывает её результат

#### Scenario: [grid-models-30] Смена пары после предыдущего результата
- **WHEN** после результата для версий 1 и 2 пользователь выбирает версии 2 и 3 или меняет направление сравнения
- **THEN** прежний результат убирается до получения результата новой пары
- **AND** при ошибке новой пары показана её ошибка, а старый результат не возвращается как новый
- **AND** результат или ошибка ранее выбранной пары, полученные после смены выбора, не подменяют результат или ошибку текущей пары

### Requirement: Сохранение прежнего сравнения при загрузке

Система SHALL сохранять прежнее сравнение загружаемой версии с базовой опубликованной версией: порядок связей не учитывается, при повторяющемся ID используется первый объект. Новые правила отдельного сравнения выбранной пары SHALL NOT распространяться на сравнение при загрузке в рамках этого изменения.

#### Scenario: [grid-models-31] Прежнее сравнение игнорирует перестановку связей
- **WHEN** пользователь загружает версию, отличающуюся от базовой опубликованной только перестановкой тех же связей объекта
- **THEN** сравнение при загрузке не показывает этот объект как изменённый
- **AND** отдельное сравнение этих сохранённых версий показывает изменение порядка связей по [grid-models-17]

#### Scenario: [grid-models-32] Прежнее сравнение использует первый объект с повторяющимся ID
- **WHEN** загружаемая версия содержит два объекта с одним ID, первый совпадает с объектом базовой опубликованной версии, а второй отличается от него
- **THEN** сравнение при загрузке использует первый объект и не показывает изменение для этого ID
- **AND** ошибка проверки повторяющегося ID сохраняется
- **AND** отдельное сравнение этих сохранённых версий исключает этот ID из обеих версий с предупреждением по [grid-models-15]
