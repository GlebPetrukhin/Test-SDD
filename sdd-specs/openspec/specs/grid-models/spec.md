# grid-models Specification

## Purpose

Обеспечить общий наблюдаемый процесс подготовки, проверки, согласования и обмена версиями моделей сети между участниками электроэнергетической системы.

## Requirements

### Requirement: Реестр моделей
Система SHALL показывать модели, организацию-владельца, регион, опубликованную версию и состояние последней версии, поддерживая поиск и фильтрацию.

#### Scenario: [grid-models-01] Поиск и просмотр
- **WHEN** пользователь открывает реестр и ищет «Урал»
- **THEN** видны подходящие модели, их версии и карточка выбранной модели
- **AND** отсутствие совпадений отображается как «Модели не найдены»

### Requirement: Создание модели
Система SHALL создавать модель по названию, региону и существующей организации-владельцу; пустые поля SHALL отклоняться.

#### Scenario: [grid-models-02] Новая модель
- **WHEN** пользователь создаёт модель «Сеть Урал» с регионом «Урал» и владельцем «Россети Урал»
- **THEN** модель появляется в реестре без опубликованной версии

### Requirement: Проверка и сравнение версий
Система SHALL сохранять неизменяемые версии JSON, показывать ошибки структуры, повторяющихся ID и несуществующих ссылок и сравнивать объекты с базовой опубликованной версией.

#### Scenario: [grid-models-03] Загрузка версии
- **WHEN** пользователь загружает JSON с массивом объектов и описанием изменения
- **THEN** появляется черновик с результатами проверки и списком добавленных, изменённых и удалённых объектов
- **AND** версия с ошибками не может быть отправлена на согласование

### Requirement: Согласование и публикация
Система SHALL поддерживать переходы draft → review → approved → published и review → rejected с обязательным комментарием возврата. Недопустимые переходы SHALL отклоняться.

#### Scenario: [grid-models-04] Прохождение согласования
- **WHEN** корректную версию отправляют на согласование, согласовывают и публикуют
- **THEN** она становится актуальной опубликованной версией
- **AND** при возврате требуется комментарий; для исправлений создаётся новая версия

### Requirement: Защита от несогласованных изменений
Система SHALL отклонять запись по устаревшей ревизии и согласование либо публикацию версии, основанной на уже заменённой опубликованной версии.

#### Scenario: [grid-models-05] Конфликт версий
- **WHEN** пользователь изменяет устаревшую карточку или публикует версию с устаревшей базой
- **THEN** отображается «Данные изменились. Обновите карточку и повторите действие.» без перезаписи чужих изменений

### Requirement: Обмен опубликованной моделью
Система SHALL скачивать JSON выбранной опубликованной версии и запрещать скачивание неопубликованных версий через функцию обмена.

#### Scenario: [grid-models-06] Скачивание
- **WHEN** пользователь скачивает опубликованную версию
- **THEN** скачанный JSON содержит исходные объекты этой версии и может использоваться для загрузки следующей

### Requirement: Прослеживаемость
Система SHALL сохранять версии и журнал действий с организацией, временем и комментарием, включая сохранность после перезапуска приложения.

#### Scenario: [grid-models-07] История действий
- **WHEN** пользователь открывает историю после создания версии и её согласования
- **THEN** видны действия, выбранные демонстрационные организации и время; данные доступны после перезапуска

### Requirement: Явные ошибки и демонстрационный режим
Система SHALL обозначать демонстрационный режим без проверки личности, показывать ошибки загрузки и предоставлять повтор запроса без выдачи демоданных за полученные с сервера.

#### Scenario: [grid-models-08] Недоступность API
- **WHEN** реестр недоступен
- **THEN** отображается «Не удалось загрузить модели» и действие «Повторить»
- **AND** на странице виден текст «Демонстрационный режим · без проверки личности»
