# Автотесты sdd-frontend

| Где | Чем | Что проверяем |
|---|---|---|
| `src/**/*.spec.ts` (рядом с кодом) | Vitest | Компоненты и сервисы (стандарт Angular) |
| `tests/e2e/` | Playwright | Пользовательские сценарии в браузере; `/api` мокается по контракту |
| `tests/e2e/*` с тегом `@smoke` | Playwright | Сквозная проверка развёрнутого стека без моков |

## Связь со спецификацией
Сценарий спецификации (`sdd-specs/openspec/specs/<capability>/spec.md`) раскладывается на тест-кейсы в
`test-cases.md` изменения. Автотест реализует один тест-кейс, его ID — в начале названия:

```ts
test('[system-status-03.2] Главная страница показывает доступность и версию', ...)
```

ID кейса начинается с ID сценария, поэтому поиск по `system-status-03` находит все тесты сценария.

- `npx playwright test --grep "system-status-03"` — E2E конкретного сценария
- `npx playwright test --grep "system-status-03.2"` — E2E конкретного тест-кейса
- Сценарий без тестов = непокрытое требование; это ловит `/opsx:verify`.
