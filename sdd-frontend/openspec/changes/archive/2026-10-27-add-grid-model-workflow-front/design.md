# Design

## Context
Ссылки на требования и контракт 1.0.0 — в proposal.md; общий design — sdd-specs/openspec/changes/archive/2026-10-27-add-grid-model-workflow/design.md.

## Decisions
Ленивая страница features/grid-models: отдельный API-сервис с HttpClient и timeout(10000), типизированные DTO; signals для данных, выбора и форм, computed для фильтра и выбранной версии. Страница содержит навигацию и статус; App предоставляет router-outlet. Основная навигация: модели, согласование (фильтр review), журнал (агрегированные события), организации (справочник).
Реестр таблицей, карточка справа на широком экране и под таблицей на узком. Состояния загрузки, ошибки, пустого результата и записи явные. Форма создания и загрузки — native dialog с возвратом фокуса, escape и именованными полями; JSON можно загрузить файлом или вставить. Ввод через form controls и signal, без нового forms-пакета. Предпросмотр модели — перечень объектов выбранной версии, без графического редактора электрической схемы. Доступные HTML-кнопки, видимый фокус, контраст, мобильная прокрутка таблицы.
E2E по 8 кейсам через page.route по контракту, отдельно сохраняются существующие тесты статуса. Кнопки действий отключены во время записи; на конфликт не сбрасывается форма и предлагается обновить карточку. Выбор версии и поиск не теряются при обновлении.

## Risks / Trade-offs
Демонстрационная организация не является учётной записью; это явно написано в интерфейсе. Без графического редактора и CIM. Список и карточка пока загружают малый реестр целиком.
